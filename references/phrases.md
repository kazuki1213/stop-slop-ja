# 削るべき語句・定型句

日本語のAI/翻訳調に特有の語句・定型句をまとめる。ここに挙げるのは、避けると日本語が自然になる「本物の癖」だけだ。**ほとんどが語そのものの全面禁止ではなく、濫用・空疎な使い方をしたときだけが対象**である点に注意する。ネイティブの優れた書き手が根拠とセットで使う表現まで禁じると、かえって硬く不自然になる(過剰適用は害)。各項目の「直す方向」と「残してよい場合」を必ずセットで読むこと。

## 前置き(throat-clearing・導入)

本題に入る前の空走り。中身を足さず、本題を一拍遅らせるだけの定型。原則は削って結論・具体例から書き出す。

| 避ける表現 | 直す方向 |
|-----------|---------|
| 「本記事では〜について解説します／ご紹介します」(中身のない単発の宣言で記事を始める) | 宣言を消し、いきなり本題(主張・結論・具体例)から書く。何の話かはタイトルとリードで伝わる。※章立てを予告する範囲設定文(「本稿ではまず…次に…」)や講演の口頭体(「本日は〜についてお話しします」)は自然なので残す。 |
| 「この記事を読めば、もう〜で悩むことはなくなり、〜できるようになります」(効能の約束) | 効能を約束する一文を丸ごと削る。読者が「できる」状態は本文の手順・具体例で作る。範囲を伝えたいなら効能でなくスコープを書く。※「この記事ではDockerの基本コマンドを扱います」のような純粋なスコープ文は正当。狙うのは「〜が身につきます／できるようになります／もう悩みません／必読です」という成果の宣言だけ。 |
| 「この記事では、以下の3つのポイントを解説します／次の点について見ていきます」(構成の口頭予告) | テンプレ的な構成予告を削り、最初の論点から具体的に書き出す。※読者を引き込む良いリード文(具体的な問い・結論の先出し)は残す。判断基準:その一文を消しても本文が成立し、消したほうが書き出しが速いなら削る。 |
| 「〜について、詳しく見ていきましょう／〜を詳しく解説していきます／ここからは〜について深掘りしていきます」(中身ゼロの深さ予告) | 予告を丸ごと削り本題に直行する。「詳しく」「深掘り」など中身を伴わない深さの予告語は捨てる。※解説動画・チュートリアルの台本など話し言葉文体では「見ていきましょう」は自然。問題は「中身ゼロの深さ予告」だけ。 |
| 「それでは、さっそく本題に入っていきましょう」(本題に入ると宣言するつなぎ) | つなぎ文を丸ごと削り、続くはずだった内容を最初の一文にする。※「さっそく具体例を3つ見ていきましょう」のように直後に具体が続くなら自然。 |
| 「皆さんは、こんな経験はありませんか?／〜と思ったことはありませんか?」(漠然とした共感釣り) | 問いかけを削り「あるある」を具体的な情景として断定で描く、または本題から始める。※鋭く具体的な問い(「なぜ締切前日だけ部屋を片付けたくなるのか?」)は残す。 |
| 「近年、〇〇が注目を集めています／話題になっています」(主語も時期も出典もない導入) | 誰が・いつ・どれだけ注目したのかを固有名詞・数字・出典で書く。背景が本筋に不要ならこの一文を丸ごと削る。※「注目を集める」自体は具体的な主語と根拠があれば使ってよい。 |
| 「昨今、〇〇が活発になっている」(漠然とした時勢で書き出す) | 事実や具体的な時点から始める。いつ・何が・どれだけ変わったかを書く。文頭に「昨今」「近年」をとりあえず置いていないか確認する。※「今や」「もはや」は強調として自然なので禁止しない。 |
| 「そもそもCVRとは何でしょうか? CVRとは、〜のことです」(定義の直前に自問→即自答) | 定義を直接書く。「〜とは、…だ／…を指す」で言い切れば問いは不要。※「そもそも前提を整理しておく」のように問いが議論の流れを作る用法、基本に立ち返る合図の「そもそも〜とは」は残す。禁止は自問→即自答の機械的な定義導入だけ。 |
| 「まずは全体構成から見ていきましょう。次に〜していきましょう」(進行の逐一実況・勧誘形の連発) | 勧誘・実況を外し対象を名詞・体言止めで直に提示する。各ステップは命令・体言止めで「次に依存パッケージを入れる」と書く。※ハンズオンで一度だけ「まずは動かしてみよう」と誘うのは自然。問題は「まずは」+「〜から」+「いきましょう」の三重の開始シグナルを各セクションで反復すること。 |
| 「ここでは〜について押さえておきましょう／まずは〜の基本を押さえましょう」(予告+勧誘形の引率) | 予告の「ここでは」と勧誘の引率を外し、扱う事項そのものを断定・列挙で示す。「〜のポイントはAとBだ」のように中身を直接書く。※実作業の手順指示(「先に環境変数を設定しておきましょう」)や一緒に手を動かすチュートリアルは残す。問題は「内容の予告」を勧誘形で包む引率トーンだけ。 |
| 「念のため申し添えますと／先に申し上げておきますと」(過剰丁寧の前置きの連発) | 本題から直接書く。補足は括弧か独立した一文で簡潔に。一段落に前置きを二つ以上重ねない。※「余談ですが」「蛇足ながら」はリズム・自己韜晦のために意図して使う正当な道具。問題は過剰敬語化と連発・情報量ゼロの緩衝材化だけ。 |
| 「いわば、データは私たちの羅針盤だ／言うなれば〜」(前置き+使い古された比喩) | 比喩が陳腐なら比喩ごと捨てて具体に書く。比喩が本当に効くなら前置きを外して直接出す。※「いわば」「言うなれば」自体は正当な修辞。判定軸は「前置きの有無」でなく「続く比喩(諸刃の剣・氷山の一角・縁の下の力持ち・羅針盤など)が本当に効いているか」。 |
| 「言うまでもなく、健康は何より大切です」(平凡な内容を権威づけで飾るだけ) | 本当に自明なら一文ごと削る。書く価値があるなら前置きを外して直接述べる。※「自明な前提→意外な論点」へ転回する praeteritio の用法(「重要なのは言うまでもないが、問題は実装だ」)は残す。NGは中身が平凡なまま飾り、転回がない場合だけ。 |
| 「市場の変化を踏まえて〜／〜を念頭に置いて〜／〜を視野に入れて〜」(枕詞化した前提提示の反復) | 前提が要るなら一度だけ簡潔に置き、以降は前置きなしで本題から書く。直前の内容を「〜を踏まえると」で言い直しそうになったらその一文ごと削る。※1回かつ内容を伴う使用(「コストを念頭に置いて設計する」)は自然。NGは(1)連続する段落の頭で反復、(2)直前の内容を追加情報なく言い直すだけ。 |
| 「現代社会を生きる私たちは、もはやAIと無縁ではいられません／〜と切っても切れない関係です」(根拠なく当事者性を煽る導入) | 誰がいつどの場面でどう関わるのかを具体的に書く。話題を大きく見せたいだけならその一文ごと削る。※本当に不可分な対象を述べる場合(「日本人と米は切っても切れない関係だ」)は自然。NGは煽りの導入として濫用するときだけ。 |

## 締め(クロージング)

中身の薄い量産記事を象徴する締めの定型。本文で価値を示し切り、末尾の願望・感謝・反復で締めない。

| 避ける表現 | 直す方向 |
|-----------|---------|
| 「いかがでしたか／いかがでしたでしょうか／参考になりましたでしょうか」 | 末尾の問いかけ自体を削除する。締めが要るなら、記事の具体的な要点か読者が次に取れる一歩を一文で書く。「いかがでしたか系記事」と蔑称されるほどの量産記事の代名詞。 |
| 「この記事が、あなたの〇〇の参考になれば幸いです／お役に立てれば嬉しいです」 | 締めの願望そのものを削り、最後の論点や次の一手で終える(例:「迷ったら、まず1on1の頻度を週1に固定するところから試してほしい」)。※私信・誠実なエッセイで実感のこもった結びは自然。NGは記事の反射的な締め文句として惰性で付ける場合だけ。 |
| 「少しでもお役に立てれば幸いです」 | 情報を伝える本文の反射的な締めとして置いているときだけ削り、結論・次の一手・優先順位で埋める。※これは元々ネイティブが使う謙遜・配慮の表現で、カジュアルなコメント・丁寧なメールでは自然。一律禁止しない。 |
| 「最後までお読みいただき、ありがとうございました」 | 締めの一文を削り、本文の結論や具体的な次の一手で終える。※ニュースレター・個人ブログ・動画台本など読者との関係性が前提の媒体で挨拶として機能する場合は残す。 |
| 「いかがでしたか。便利なツールなので、ぜひチェックしてみてくださいね」(中身のない汎用CTA) | 勧めるなら、何を・どこで・どう始めるか、読者が何を得るかを具体的に書く。書けないなら一文ごと削る。「ぜひ」「〜してみて」を外し対象と最初の一歩を名指しにする。※対象が具体的な「ぜひ」(数量限定なので早めに)は自然。 |
| 「気になる方はぜひチェックしてみてください。詳しくは公式サイトをご覧ください」(本文を空にしてリンクに丸投げ) | 本文で判断に足る情報(対象・要点・向き不向き)を示す。リンクは「何を確認するためか」を具体的に書く。漠然とした「気になる方は」「ぜひ」「〜してみてください」の丸投げ語調を削る。※価格・締切など変動情報の一次ソースを示す「詳しくは公式サイトを」は、本文に要点がある限り正当。 |
| 「あなたも今日から〇〇を始めてみませんか／さあ、今すぐ第一歩を踏み出しましょう」(二人称+作為的な緊急性+煽り) | 煽り文句と二人称「あなた」を外す。始める価値があるなら理由か最初の一歩を具体的な事実で示して終える。※勧誘形「〜してみませんか」自体は自然。NGは「あなたも＋今日から＋抽象的な効能(人生が変わる等)」の組み合わせ。 |
| 「〇〇の世界は奥が深いですね／可能性は無限大です／まだまだ可能性を秘めています」(スケール感だけの空虚な締め) | 「深さ」「可能性」をスケール感だけで語る定型は削る。伝えたいなら具体例を一つ示して終える(「次は〜を試したい」)。※「この設定は奥が深い」のように実質を伴って本文中で使うのは自然。「ですね」は読者の同意を勝手に取りつける馴れ合いの語尾なので注意。 |
| 「結局、大切なのはデータです。データを制する者がビジネスを制するのです」(格言・ポエムでの締め) | 格言・情緒でのまとめをやめる。押さえるべき点があるなら、なぜ効くのかを具体的な行動・数字に落とす。本文の言い換えなら締めごと削る。「Xを制する者がYを制する」「結局／つまるところ大切なのは〜です」は既存格言の鋳型に語を流し込むだけの同義反復。 |
| 「皆さんも、自分に合った〇〇を見つけてみてください／最終的には自分に合うものを選ぶのが一番です」(判断の丸投げ) | 書き手として一つ推す。比較したなら「迷ったらこれ」を名指しし、選ぶ基準を一つ示す。読者は何を選ぶべきか知りたくて読んでいる。 |
| 「ご不明な点がございましたら、お気軽にお問い合わせください」(窓口の実体がないのに貼る汎用フッター) | 実体のある窓口がある場合だけ、何について・どこへ連絡してほしいかを具体的に書く(例:「エラーコードE-12が出る場合は support@example.com に連絡してください」)。窓口がない汎用の締めは丸ごと削り、本文を最後の要点で終える。 |
| 「ぜひ参考にしていただき、〇〇に役立てていただければと思います」(価値判断の二重の丸投げ) | 丸ごと削るのが基本。背中を押したいなら、丸投げの願望でなく具体的な使いどころを一つ示す(「まずは来月のレポートで試してみてください」)。 |

## 締め(進行をなぞる・反復するまとめ)

末尾で本文をそのまま要約し直すだけの「振り返り宣言」。新情報がなく、記事が自分の目次・進行をなぞる。

| 避ける表現 | 直す方向 |
|-----------|---------|
| 「今回は、〇〇について解説しました／まとめると〇〇でした」(本文の単純な反復) | 単なる反復なら丸ごと削る。締めくくるなら、要点を踏まえて判断・結論・次の一手へ進める。※「まとめると」「要するに」で長文を本当に統合する締めや、長い技術文書での短い要点整理は正当。NGは内容を反復するだけのとき。 |
| 「本記事では〇〇について見てきました／ここまで〇〇について解説してきました」(進行のナレーション) | 新しい情報がゼロなら丸ごと削る。締めには記事全体の結論・判断・次の一手(持ち帰る一文)を置く。長文では「全部を踏まえると何が言えるか」という統合を書く。※中身のある総括(全体を踏まえた結論・トレードオフ提示)は歓迎。 |

## 空虚な強調(ブースター・誇張)

程度を具体化せず強さだけ主張する語。情報量ゼロで、積み重なると機械的・幼稚に読める。**語そのものは禁止しない。形容詞ごとの反射的な貼り付け・連発のときだけ**削るか具体(数字・比較・帰結)に置き換える。

| 避ける表現 | 直す方向 |
|-----------|---------|
| 「とても／非常に／極めて」を形容詞ごとに反射的に貼る・連続させる | 反射的に付けたブースターを削る。同じブースターが複数の文で繰り返されたら、一番効く一箇所だけ残して他は削る。程度が要点なら数字・比較・具体例に置き換える(「非常に速い」→「従来の3倍の速度」)。※一文に一度、本当に効く箇所で使うのは自然。 |
| 「本当に便利で、本当に役立ちます」(評価形容詞への根拠なき主観強調) | 「本当に〜」を削り、なぜ便利・役立つかを具体的に書く。※「本当に申し訳ない」「本当に困った」のように感情・状態を述べる用法、文語的な「実に」は禁止しない。狙うのは評価形容詞(重要・便利・面白い等)への根拠なき上乗せだけ。 |
| 「まさに革命的です／まさに理想的と言えるでしょう」(空疎な賛辞を増幅する「まさに〜です」) | 「まさに」も賛辞(画期的・革命的・理想的・最先端など)も消し、具体的な事実・数字に置き換える。※「まさに今」「まさにその点が」「まさにその通り」のように時間・論点を一点に絞る用法は残す。「まさに」を語として一律禁止にしない。 |
| 「驚くほど多くのユーザーが、驚異的な満足度を示した」(感想を押し付けるブースター) | 「驚くほど／驚異的な」を消し、驚きに値する数字や事実そのものを見せる(「回答した1,200人のうち94%が『また使いたい』と答えた」)。※「数字を見て驚いた」のように具体的原因に紐づく叙述、随筆での率直な感情表現は残す。NGは裏づけなしの連体修飾。 |
| 「圧倒的な品質を実現／圧倒的に使いやすい」(根拠なき優位の主張) | 何に対して(比較対象)・どれだけ(数字・差)優れるかを必ず添える。添えられないなら強調自体を削る。※「圧倒的多数で可決」「圧倒的な点差」のように差が明らかな用法は自然。 |
| 「革新的なAI議事録ツールが登場。会議のあり方を変える画期的なソリューション」(中身ゼロの持ち上げ) | 形容詞を削り「従来は何ができず・どう面倒だったか」「それがどう変わるか(数値・手順・仕組み)」を一文で書く。※「革命的／画期的／革新的」は実証を伴えば正規語(「iPhoneは画期的だった」)。NGは形容詞だけで持ち上げ中身を書かないとき。特に「革新的／イノベーティブ」は空でも貼れるので要注意。 |
| 「究極のガイド／至高の一杯／究極のソリューション」(根拠のない最上級) | 根拠のない「究極／至高」を削り、具体的な強み(何が・どれだけ・どう良いか)に置き換える。※「最高」は日常語で、実感を述べる用法(「あの店のラーメンは最高だった」)は自然。NGは対象に外から貼った裏付けのない宣伝文句。 |
| 「唯一無二の体験を提供する、他に類を見ないサービス」(証明せず宣言するだけの差別化) | 「他とどう違うか」を具体的に一点示す。比較対象と差分(数字・仕様・できること)を出せれば「唯一無二」と書く必要は消える。示せないなら主張ごと削る。※人物・作品の代替不可能性を述べる用法は残す。 |
| 「日本一の品質と言っても過言ではないでしょう」(予防線で誇張を盛る) | 前置きを削って普通に断定する(「不可欠です」)。断定しても中身が空虚なら主張自体が弱い証拠なので、具体的な数字・事実に置き換える。※「大胆だが妥当」と明示する議論文での限定的使用までは禁じない。 |
| 「計り知れない価値／計り知れない可能性／計り知れない影響」(規模を測る責任を放棄した賛辞) | まず削る。残すなら具体的な数字・期間・変化に書き換える(「コストを3割削減」)。※「被害の大きさは計り知れない」のように本当に測定不能なものを指す正統な用法は残す。判断軸は対象が抽象的な賛辞名詞かどうか。 |
| 「動作速度が大幅に向上し、ユーザー体験が飛躍的に改善しました」(数字を伏せた誇張) | 具体的な数値か前後比較に置き換える(「起動時間が4.2秒から1.1秒に短縮」)。数値が不要な文脈なら強調語を削り動詞だけ残す。※「大幅に値下げした」のように事実に密着した用法は自然。判断軸は「数字を伏せて誇張していないか」。「飛躍的に」は特にhype色が強い。 |

## 空虚な強調(重要性の宣言)

中身を見せる前に「重要だ」と宣言する前置き。読者に判断材料を渡さず結論だけ押しつける。**「重要」「不可欠」という語は禁止しない。根拠を一切示さず価値だけ宣言する使い方**だけが対象。

| 避ける表現 | 直す方向 |
|-----------|---------|
| 「〇〇は非常に重要です／重要な要素です／〜する上で欠かせない」(根拠なき価値づけの宣言) | 価値づけの宣言を削り、なぜ重要かを示す事実・数字・帰結を直接書く。具体を一つ示せば読者が自分で判断できる。※具体的な根拠とセットで使う「重要だ」は自然。 |
| 「この設定は極めて重要です。不可欠な要素と言えるでしょう」(中身のない強調ラベル) | (1)「何にとって・どうなるか」を示さず重要だと言い張る一文は削る(多くは削っても文意が通る)。(2)残すなら重要さの中身=対象と帰結を書く。「極めて」「非常に」の上乗せは具体を書けば不要。 |
| 「日々の運動は健康維持に不可欠です。良質な睡眠も欠かせません」(裸の重要性宣言の連発) | それがないと具体的に何が起こるか(因果)、または数値・固有名・場面で裏づける。本当に必須なら因果を書けば「不可欠」は不要。※「登録にはメールアドレスが必須」のように必要性が事実として確定している場合は残す。連発は最優先で削る。 |
| 「テストを書くことの重要性はいくら強調してもしすぎることはありません」(英語 cannot be overstated の翻訳調) | 「重要だ」という宣言を丸ごと削り、なぜ重要かを書く。書かないと何が起きるかを一文で示す。※文法「いくら〜してもしすぎることはない」自体は、具体的な行為や結果に対して使う分には自然。 |
| 「セキュリティ対策においては、適切なリスク管理を行うことが重要です／継続的な改善が求められます」(中身のない当為の締め) | 何をどうすべきかを具体的な行動・主体・基準として書く(「パスワードは12文字以上にし、多要素認証を全アカウントで有効にする」)。当為で締めるのは直前に具体策を示し終えたときだけ。 |
| 「継続的な改善を続けていくことが大切です」(具体ゼロで段落を閉じる教訓化) | 段落を価値判断で締めない。締めは具体的な事実・とった行動・出た結果で終える。主張で締めたいなら直後に根拠を一行足す。※「重要／大切」は論証の途中で根拠付きなら普通に使ってよい。語狩りはしない。 |

## 空虚な宣言(具体を言わない・断定を避ける)

主体・理由・程度を省いたまま「大事そう」とだけ言う癖。英語版 Vague Declaratives の日本語版。視点・観点・側面・関係を名指すだけで、中身が続かない。

| 避ける表現 | 直す方向 |
|-----------|---------|
| 「DX推進が課題となっています／組織の対応力が問われています」(無人称の宣言) | 誰が・何に・どう困っているのかを具体で書く(「教えられる先輩が二人しかいない。その二人とも来年で定年だ」)。※具体を伴う「納期短縮が課題だ」は正常。NGは具体のない宣言と、もったいぶった「〜となっています／問われています」形。 |
| 「DX推進の必要性が指摘されています。重要性も高まっています」(抽象名詞主語+受身の宣言) | 主体(誰が)・きっかけ(なぜ)・程度(どれだけ)の少なくとも一つを具体名詞で埋める。「指摘されています」「求められています」と行為者を隠す受身が出たら危険信号。※「需要が高まっている」のように具体物が主語で実際の変化を述べる文は対象外。 |
| 「DX推進にあたっては、社員一人ひとりの主体的な姿勢が求められています」(無人称の当為宣言) | 誰が・誰に・何をするのかを立て、「〜する必要がある」「〜すべきだ」「〜しよう」と言い切る。可能なら具体的な行動に置き換える。※「高い精度が求められる作業」のような連体修飾、「彼に説明を求めた」のような能動の他動詞用法は自然。NGは空疎な抽象名詞主語+無人称の「求められます」。 |
| 「〇〇という観点が重要です／これらの観点を踏まえると」(視点名を挙げるだけで何が見えたかが続かない) | 観点を宣言して止めない。その視点で見えた具体を直接書く。※「コストの観点では、この案は月20万円高い」のように視点の直後に具体が続くなら自然。NGは宣言して文が終わる/抽象論に逃げる用法。 |
| 「リモートワークには、生産性が上がるという側面があります」(中身を名指さないラッパー) | 一点なら言い切る。本当に複数の次元があるときだけ「側面」を使い、各次元を具体的に挙げる。※「技術的側面と倫理的側面」のように複数次元を名指す用法は正当。NGは単一の具体点を抽象名詞「側面」で包む使い方。 |
| 「プロジェクト成功の鍵となるのは、チーム間の連携です」(重要性の煽りとしての「鍵」) | 「Aがないと何が起きるか」「Aが何をどう左右するか」を書く(「週1の同期会議がないと各チームの仕様がずれて手戻りが出る」)。※「鍵を握るのは現場の判断だ」のように具体に分かる比喩は自然。NGは抽象語を「鍵」に祭り上げる話題提示。 |
| 「大切なのはユーザー視点を持つという点です」(クレフト構文の反復+「という点です」padding) | 「重要なのは〜だ」の宣言を削り中身を直接置く。連発しているなら一度だけに絞る。「という点です／ということです」は素の「〜だ／〜です」か体言止めにする。※一度きりの強調「大切なのは〜だ」は自然。 |
| 「この機能を使う上でポイントになるのは、〜という点です／〜がポイントになります」(空虚な予告枠+「になります」) | 空虚な予告・締めの「ポイントは〜です」を外し要点そのものを言い切る。曖昧な「〜になります」は「〜です」か言い切りに直す。※複数の要点を実際に整理・列挙する「ポイントは2つ」は残す。 |
| 「〇〇といったことが挙げられます／〇〇なども考えられます」(曖昧な例示+無人称の提示動詞) | 例を絞って言い切る。列挙するなら「主な利点は二つ」と数を明示し各項目を具体値で書く。※対象が具体的な「コスト削減と効率化が挙げられます」は自然。NGは「といったこと／など」のぼかし+無人称+具体性ゼロが揃ったとき。 |
| 「枚挙にいとまがない／多岐にわたる／多種多様」(具体例を挙げず量だけ宣言) | 代表例を2〜3個、固有名詞や数字で挙げる。挙げられないなら誇張自体を削る。※「業務は経理から法務まで多岐にわたる」のように直後で中身を示すなら自然。NGは量を宣言して具体を省く「網羅を装う」用法。 |
| 「この問題は地域経済と深く結びついています／食生活は寿命と密接に関係しています」(関係を断言して終わり) | 「AはBを〜する」「AがCだとBはDになる」と作用・因果を一文で具体的に示す(「睡眠が足りないと、血糖を調整するホルモンが乱れ、太りやすくなる」)。※次の文で必ずメカニズムを説明できるなら切り出しに使ってよい。NGは関係を言うだけで止まる空振り。 |
| 「毎日の運動は健康維持につながります／〜へとつながっていきます」(機構を示さない利益提示) | 具体的な因果動詞(高まる・減る・早まる・崩れる等)に置き換え「Aすると(理由)Bになる」と機構を一文で示す。※「この判決は制度の見直しにつながった」のような健全な因果は残す。進行形「〜ていきます」は特に誇張のサインなので優先的に疑う。 |
| 「京都ならではの魅力を、ぜひ現地で味わってみてください」(中身のない特別感) | 違いを名指しできるなら「〜ならでは」を使ってよい。名指しできないなら一文ごと削るか具体的な事実に置き換える。「具体的に何が?」と自問し、答えられないなら褒め言葉自体を消す。 |
| 「リソースが足りないので、来期に見送ります」(具体を避ける抽象語) | 何が足りないのかを名指しする(人手・時間・予算・エンジニアの稼働など)。※計算資源・有限資源など抽象を意図して指す場合、業界の定着用法は自然。NGは中身が特定できるのに「リソース」でぼかすとき。 |
| 「プロジェクトは新たなフェーズへと移行し、次のフェーズに向けて前進している」(中身のない進行宣言) | 「フェーズ」という語は禁止しない。何が・なぜ・どう変わるのかを具体的に書く(「9月に決済機能を実装し、10月から既存顧客100社へ先行提供する」)。※「設計フェーズ」「フェーズ1/2」は自然。NGは中身のない進行宣言の濫用だけ。 |
| 「コードのこの部分／〜という部分」(抽象語に付くぼかしの「部分」) | 抽象的な名詞に付いた飾りの「〜の部分」を削る(「価格の部分」→「価格」)。さらに踏み込めるなら何が問題かを具体的に書く(「使い勝手の部分が課題」→「ボタンが小さくて押しにくい」)。※実体のある箇所(コードの一部、文書の段落、物理的箇所)を指す「部分」は残す。 |
| 「ある意味成功したという意味で、評価できる部分もある」(意味を特定しない空虚なヘッジ) | 「どの意味で」かを数字や事実で具体化する。できないなら留保ごと削って言い切る。※意味を限定する正当な用法(「本当の意味で」「広い意味で」「いい意味で」)は残す。NGはどの意味か示さず断定を薄めるとき。 |

## 冗長・水増し

動詞・断定で足りるところを、名詞化や言い直しで膨らませる癖。多くは圧縮しても意味が変わらない。

| 避ける表現 | 直す方向 |
|-----------|---------|
| 「予約をキャンセルすることができます」(「することができる」の冗長) | 動詞+「できます」へ圧縮する(「予約はキャンセルできます」)。まず本当に可能の表現が要るかも見直す(命令・断定で足りる箇所も多い)。※動詞を残さないと意味が変わる場合やリズムの都合でまれに残す判断はあり得る。問題は癖としての反復・濫用。 |
| 「本サービスは無料となっております／会員登録が必要となっています」(静的事実の状態化) | 「です」で言い切る(「本サービスは無料です」)。※「画面が暗くなっています」「在庫切れになっています」のように変化した結果の状態を述べる「〜になっています」は残す。線引きは「単純な事実か／変化・結果の状態か」。 |
| 「価格を下げれば客は増える。要するに、売上が伸びるということです」(言い直しオチ・二度書き) | 言い直しの一文を削り、結論を一度だけ書く。※伝聞(「明日は雨ということです」)や本物の論理的帰結・正式な決定(「来月から移行することになります」)は自然。NGは直前の内容を「つまり〜ということだ」と回収する二度書き。 |
| 「差別化を図ることが重要となってきます」(「となってくる」での水増し) | 「だんだん/徐々に」を補えるか試す。補えない=時間変化でないなら「〜が重要だ」「〜が必要だ」「〜しよう」と言い切る。※本当に段階的変化を述べる「年を取ると体力が気になってくる」は残す。 |
| 「いったんこの形で進めて、来週調整しましょう」型でも「〜という形になります／です」(空クッションの「形」) | 「形」が実体(やり方・体裁・枠組み)を指さず、外しても意味が変わらないときだけ「という形」を削って言い切る(「納品は来週末です」)。※「この形で」「別の形で」のように具体的なやり方・体裁を指す場合は残す。 |
| 「単に処理が速いだけでなく、コストも安く、運用が楽なだけでなく、拡張性も高い」(対比枠への反射的な流し込み) | 対等に並ぶ要素は「と」「に加えて」で並べるか二文に分ける。対比枠は後半に本当に重みを置きたいときだけ残す。「単に〜なだけでなく」「〜というだけでなく」と前置きを重ねた形はほぼ削れる。※「〜だけでなく」自体は自然。NGは大げさな対比化・連発。 |

## 抽象名詞化の濫用(〜化・〜性・〜的)

接尾辞「〜化」「〜性」「〜的」を付けて、具体的な動作や事物をぼかした抽象名詞に逃がす癖。翻訳調・官公庁調の典型。**接尾辞そのものは禁止しない。** 定着語や、品質・程度が論点の箇所は自然。狙うのは、外しても意味が変わらない飾りの抽象化。

| 避ける表現 | 直す方向 |
|-----------|---------|
| 「業務の効率化を実現する」「DX化を推進する」(動作を「〜化＋する」でぼかす) | 何をどうするかを動詞で書く(「請求処理を自動化し、月20時間を2時間にする」)。中身を伴う定着語(自動化・電子化)は残す。 |
| 「柔軟性のある運用」「拡張性が高い」「ビジネス的な課題」(程度・分野を「〜性／〜的」で抽象化) | 程度が論点なら数字・具体で示す(「設定を変えずに同時接続を10倍にできる」)。「ビジネス的」は「営業上」「費用面」など具体に。学術・技術の定着語(再現性・可逆性)は残す。 |

## 過剰丁寧・敬語の濫用

正しい敬語でも、全文に・何重にも・場面を問わず掛けると慇懃無礼でAI調になる。**フレーズ自体は禁止せず、濫用と多重スタックだけ**を狙う。

| 避ける表現 | 直す方向 |
|-----------|---------|
| 「ご紹介させていただきます／説明させていただき／質問させていただければと思います」(「させていただく」の濫用) | 許可・恩恵が関わらない動作は「します」「いたします」で十分。一文・一段落に何度も並べない。※相手の許可・指示があり自分に恩恵が生じる動作(「本日対応させていただきます」)では正しい謙譲表現なので残す。 |
| 「お忙しいところ大変恐縮ですが、ご確認いただけますと幸いです。ご不明点等ございましたら、お気軽に〜いただければと存じます。何卒〜」(依頼緩衝の多重スタック) | 深い緩衝は本当に重い依頼1か所に絞り、残りは「ご確認ください」「お知らせください」に下げる。同じ緩衝形を反復しない。相手・場面(register)に応じて使い分ける。※「していただけますと幸いです」自体は正しい敬語。一律「してください」化はクライアント・目上に無礼になりうる。 |

## 指示語の濫用(こちら)

対象を名指しできる場面で「こちら」を曖昧なまま多用する癖。丁寧に見えて、何を指すかを書く手間を省いているだけ。ビジネス文書・SaaS紹介文に頻出。

| 避ける表現 | 直す方向 |
|-----------|---------|
| 「詳しくはこちらをご覧ください」「こちらのツールがおすすめです」(対象を名指しせず「こちら」で済ます) | 指す対象を名詞で書く(「詳しくは料金ページを見てください」「このツールがおすすめです」)。「こちら」を「この◯◯」に直して意味が変わらないなら直す。※方向・場所を指す用法や、接客・電話で相手と自分を指す「こちら」は自然。 |

## カタカナ語の濫用

定着した和語があるのに横文字に置き換えただけの語。読みにくさと気取りだけが増す。**AI固有の癖というより文体・register のクリーンアップ**であり、定着した複合語・専門用語・口語は残す。

| 避ける表現 | 直す方向 |
|-----------|---------|
| 定番の漢字語があるビジネス英語のカタカナ化(バジェット→予算、アサイン→割り当て・担当、プライオリティ→優先順位、エビデンス→根拠、コミット→約束・確約) | 一般の文章では漢字語に戻し、誰が誰に何をするかを明示する。判断基準:「そのカタカナを漢字語1語に直しても意味も自然さも損なわれないか」。※定着して言い換えると不自然になる語(バジェットホテル、ローバジェット映画、リスク、コスト)は残す。 |
| 「アサイン」(PM/IT文脈以外での濫用) | 一般の文章では「割り当てる」「担当を決める」「任命する」「振る」に置き換える。※IT/プロジェクト管理・人材配置・口語で定着している場合は許容し、無理に和語化しない。 |
| 「プライオリティ」(書き言葉での濫用) | 定着した和語(優先順位・優先度)に置き換えられる箇所だけ直す。※外資系の社内文書・チャットなど、媒体・読者の文体に馴染む文脈では残してよい。 |
| 「ナレッジ」(「知見・知識・ノウハウ」の単なる言い換え) | 文脈に合う和語(知見・知識・ノウハウ・経験)に戻し、何を共有・蓄積するのかを一語で名指しする。判断基準:「知見」「ノウハウ」に置き換えて意味が通るなら置き換える。※「ナレッジマネジメント」「ナレッジベース」など定着した複合語は残す。 |
| 「スキーム」(一般向けで「やり方／方針」をぼかす濫用) | 一般向けで「やり方／方針／段取り」程度をぼかしているときだけ「仕組み」「枠組み」「やり方」「段取り」に言い換える。※金融・法務・M&Aで具体的な構造を指す確立した専門語(事業スキーム、ファイナンススキーム)は残す。 |

## ヘッジ・断定回避

断定を避けて主体・確信度をぼかす弱い語尾。AIが文末に反射的に付ける。**単独の推量・留保は自然。二段重ね、または断定できる主張への反射的な付与**だけが対象。

| 避ける表現 | 直す方向 |
|-----------|---------|
| 「〜と言える／言っても過言ではない」を事実にまで機械的に付ける | 言い切れることは「〜です／〜する」で断定する。「〜と言っても過言ではない」は誇張ヘッジなので原則削る。※「でしょう／だろう」は本当に推量・留保が要る箇所だけに残す。 |
| 「〜のではないでしょうか」を断定できる主張に連発する | 根拠があって言える主張は「〜です／〜べきです」と言い切る。委ねたい提案は「〜してはどうでしょう」「〜する手もあります」と具体的行動に落とす。※意図的に1回だけ、本当に問いかけたい場面に残す。 |
| 「〜ではないかと思われます」(否定+推量+受動の三重ヘッジ) | 「〜です／〜べきです」と言い切る。※深刻度の高い三重ヘッジを優先的に潰す。「〜のではないでしょうか」単独はより軽い軟化なので濫用時のみ。 |
| 「〜と考えられます／思われます」を主張を担う文脈で連発する | 自分の判断なら言い切る(「〜と考えます」「〜です」)。根拠があるなら主体を出す(「調査では〜が分かりました」)。同一段落で推量止めを連発しない。※論文・調査報告・技術文書など客観記述が規範の文脈では正しい文体なので直さない。NGは言い切れる立場の書き手が保身的に連発するとき。 |
| 「効果があると言えるかもしれません。〜と言っても良いでしょう」(主張のメタ枠+法助動詞の二重緩衝) | 緩衝は一段までにする。二重緩衝(「〜と言える」+「でしょう／かもしれません」)を禁止する。計測前で確証がない箇所だけ一段の留保を残す。※単一の緩衝(「〜だろう」「〜と言える」だけ)は自然。 |
| 「効果があるのではないかと思われます」(「〜のではないか」+「思われます」の二重ぼかし) | 自分の見立てなら一段の推量に(「効果があると思う」)。根拠があるなら断定する(「効果がある」)。見込みなら「効果が見込める」。※「〜と考えられる」単体、「〜のではないか」単体は自然。NGは二つを重ねたとき・文末の常套句として濫用するとき。 |
| 「設定を見直してみてはいかがでしょうか。〜するのも良いでしょう」(提案の定型の連発) | 提案は理由・条件とセットで具体的に書くか、命令形・平叙文で直接示す。反射的な締めとして連発しない。文末が「〜でしょうか／〜でしょう」で揃ったら崩す。※1文に1回程度・本当に判断を委ねたい場面は自然。 |
| 「残念な結果と言わざるを得ません」(抵抗の実体がない渋々ポーズ) | 渋々の体裁を外し「〜だ／〜である」と断定する。※本当に「言いたくないが事実が結論を強いる」状況(辛口の批評・反証を踏まえた結論)では緊張を示す装置として残す。NGは抵抗の実体がない単なる断定に被せるとき。 |
| 「価値を生むのは、地道な改善の積み重ねこそが本質に他なりません」(語調だけの決め台詞) | 普通に「〜だ」と述べる。強調したいなら、なぜそう言えるかを具体例・根拠で示す。※「こそ」単体(「今こそ」「これこそ」)、文語として効く「に他ならない」は自然。NGは薄い結論を「これこそが本質／答えだ」と格上げする決め台詞。 |

## 推測+反転・煽り

読者がまだ抱いてもいない感情を仮定してから打ち消す、または不安を煽る型。情報量ゼロのまま字数だけ食う。

| 避ける表現 | 直す方向 |
|-----------|---------|
| 「APIと聞くと難しそうに感じるかもしれませんが、実はとても簡単です」(感情の推測+お決まりの反転) | 心理の推測と反転を消し、対象そのものを端的に説明する。簡単さは形容詞で主張せず、手順の短さ・所要時間・必要なものの少なさで示す(「APIの設定は3ステップで終わる」)。※読者の懸念に本当に触れる必要があるときだけ、推測形を使わず事実として書く。NGは「難しそう→実は簡単」のテンプレ運用。 |

## 翻訳調の無生物主語・授受表現

英語の help you / let you / allow you を直訳した、無生物主語+授受表現。押しつけがましい偽の温かさが出る。**人を主語にした授受表現はネイティブの自然な日本語なので残す。**

| 避ける表現 | 直す方向 |
|-----------|---------|
| 「このツールがデータを自動で整理してくれます／グラフがトレンドを教えてくれます」(無生物主語+「〜してくれる」) | 恩恵のニュアンスを外し素の動詞・可能形にする(「このツールでデータを自動で整理できます」「グラフからトレンドが読み取れます」)。※人や組織が主語で恩恵が実在する場合(「同僚が引き受けてくれた」「読者が最後まで読んでくれた」)は触らない。 |

## 翻訳調の枠組み動詞

同じ枠組み動詞を機械的に反復する、または抽象概念に literal な比喩を当てる癖。

| 避ける表現 | 直す方向 |
|-----------|---------|
| 「本記事は〜にスポットライトを当て、その戦略にスポットライトを当てていきます」(shine a light on の直訳+反復) | 抽象的な対象への「スポットライトを当てる／光を当てる」は「取り上げる」「紹介する」「中心に扱う」「〜について」に置き換える。同じ比喩動詞を一文書内で反復したら2回目以降は別の動詞に散らす。※「焦点を当てる」は論文・報道で定着した自然な日本語比喩なので禁止しない。判断基準:比喩を消して「〜を中心に／〜について」で意味が同じなら飾りなので削る。 |

## 推奨・行動喚起の連発

理由を省いて推奨フレーズだけをセクションごとに反復する量産記事・アフィリエイト調の癖。**推奨表現自体は禁止しない。理由なしの連発**だけが対象。

| 避ける表現 | 直す方向 |
|-----------|---------|
| 「朝はホットコーヒーがおすすめです。昼は炭酸水がおすすめです。夜はカモミールティーをおすすめします」(理由なしの「おすすめ」連発) | 「おすすめ」連発を削り、勧める根拠を一つ具体的に書く(「集中したい午後はカフェインの抜けたカモミールティーにすると、夕方の眠気で作業が止まらない」)。理由が言えないなら勧めない。※理由とセットの単発の推奨は自然。 |
